Executive 1-Page Summary
1. System Architecture Overview
■ Part 1: Support Email Agent
  • Pre-Draft Routing: Deteksi instan kata kunci kritis (data loss, outage, breach) dan kontak berulang (>3x dalam 7 hari).
  • Intent Classifier: Pengelompokan terstruktur (Billing, Technical, Feedback).
  • Grounded RAG: Respons hanya dari internal KB; strict zero-hallucination guardrail pada refund policy.
■ Part 2: Web Scraper & Summarizer
  • Adaptive Scraping: Fast HTTP Requests + fallback otomatis ke headless Playwright untuk dynamic SPA/JS.
  • DOM Cleaning: Pembersihan tag non-konten dan seleksi kontainer <article>, <main>.
  • Fact Map-Reduce: Sliding-window chunking untuk teks panjang + validasi panjang 100–250 kata.
■ Part 3: LangGraph Academic Agent
  • State Machine DAG: Alur terorkestrasi (Guard → Thinking → Tools → Generator).
  • Autonomous Tool Decision: LLM structured output (Pydantic) memilih selektif antara 134-hlm KB dan Web.
  • Persistent Memory: SQLite checkpointer untuk multi-turn chat + FastAPI SSE token streaming.
2. Key Engineering Trade-offs Made
Dimensi Trade-off Pilihan Desain yang Diambil Rasional & Dampak Operasional
Automation vs. Safety (Part 1) Eskalasi manusia pre-drafting untuk isu kritis & tiket frekuensi tinggi (>3x/7 hari). Menurunkan rasio otomasi otomatis, namun 100% meniadakan risiko komitmen salah (*liability*) atau halusinasi pada krisis layanan.
Latency vs. JS Support (Part 2) Pendekatan hibrida: HTTP Requests (primer) + Playwright (fallback bersyarat). Menghemat konsumsi CPU & latensi pada 80%+ situs web statis biasa tanpa kehilangan kapabilitas rendering pada aplikasi web dinamis.
Window vs. Map-Reduce (Part 2) Sliding-window chunking + sintesis fakta bertingkat untuk dokumen melebihi threshold. Membutuhkan lebih dari satu API call, namun mencegah hilangnya poin penting di akhir halaman (*loss in the middle*) secara total.
Strict Scope vs. Chat Coverage (Part 3) Polite guardrail node aktif menyaring kueri di luar penulisan karya ilmiah UM. Agen tidak melayani obrolan umum di luar domain, tetapi menghemat kuota token LLM dan menjaga integritas akademik institusi.
3. Potential Failure Points & Mitigations
Potensi Titik Kegagalan Analisis Risiko / Dampak Mekanisme Mitigasi yang Diimplementasikan
Refund Policy Hallucination LLM mengarang terms pengembalian dana yang merugikan finansial perusahaan. Pengecekan berbasis dokumen internal strictly grounded; jika tidak tercantum, agen menolak asumsi dan meneruskan ke tim finansial manual.
Missed Critical Technical Event Downtime atau kebocoran data tertunda karena antrean drafting normal. Guardrail verifikasi berbasis aturan (rule-based trigger) dieksekusi di gerbang awal sebelum LLM drafting dipanggil.
Summary Drift & Verbosity Output ringkasan terlalu pendek atau melampaui batas batas panjang. Programmatic word-counter guardrail (100–250 kata) dengan mekanisme retry otomatis terstruktur (maksimal 3 kali).
Stale Literature & Time Drift Rujukan usang >10 tahun disarankan mahasiswa karena model tidak tahu tahun ini. Modul time-awareness dinamis menyuntikkan tanggal riil sistem & semester berjalan, menghitung rentang 10 tahun (2016–2026).
API Downtime / Rate-Limits Kegagalan jaringan atau kuota Gemini API habis (429/503). Implementasi exponential backoff retry loop, fallback parser terstruktur, dan isolasi thread pada server FastAPI SSE.
